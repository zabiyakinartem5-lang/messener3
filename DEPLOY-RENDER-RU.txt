# Размещение Messenger на Render

## Что уже настроено
- Node.js-сервер и WebSocket запускаются из Dockerfile проекта.
- SQLite и загруженные файлы хранятся на постоянном диске `/data`.
- ИИ отключён, чтобы не тратить ресурсы сервера.
- Health check: `/api/health`.

## Как запустить
1. Создайте аккаунт на https://render.com.
2. Создайте новый пустой репозиторий на GitHub.
3. Распакуйте этот архив и загрузите **содержимое папки `messenger`** в корень репозитория (там должны лежать `Dockerfile`, `package.json`, `render.yaml`, папки `server`, `client`, `public`).
4. В Render нажмите **New → Blueprint** и подключите этот GitHub-репозиторий.
5. Render прочитает `render.yaml`. Подтвердите создание сервиса и дождитесь статуса **Live**.
6. Откройте выданный Render URL вида `https://messenger-xxxx.onrender.com`.

## Важно
- В конфигурации выбран план Starter, потому что приложению нужен постоянный диск для SQLite и файлов. Уточните актуальную цену в Render перед подтверждением.
- Не удаляйте persistent disk: там будут аккаунты, переписки, подарки и загруженные файлы.
- Первый зарегистрированный аккаунт становится администратором. После регистрации откройте меню → Admin panel → Access и включите Invite only, чтобы посторонние не могли регистрироваться.
- Этот проект не является статическим сайтом. Не загружайте его как обычный Netlify Deploy: API и WebSocket должны работать на Node-сервере.
- Я не могу войти в ваш Render/GitHub аккаунт или нажать Deploy за вас. После загрузки пришлите Render URL или текст ошибки — помогу проверить запуск.
