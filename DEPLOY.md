# Как запустить мессенджер для 2–3 человек

Я не могу разместить сервер за вас: у меня нет доступа к вашим аккаунтам и платежам. Но всё нужное уже в этой папке.
Ниже три способа, от самого быстрого к самому надёжному.

## Способ 1. С вашего компьютера, бесплатно (за 15 минут, для пробы)

Подходит, чтобы друзья попробовали уже сегодня. Минус: пока ваш компьютер выключен или спит, мессенджер недоступен.

1. Запустите мессенджер как обычно: `npm install`, `npm run build`, `npm start`.
2. Установите Cloudflare Tunnel (`cloudflared`, cloudflare.com/products/tunnel).
3. В другом окне терминала: `cloudflared tunnel --url http://localhost:3000`
4. Cloudflare напечатает адрес вида `https://что-то-там.trycloudflare.com`. Отправьте его друзьям.
5. Запускайте мессенджер с `TRUST_PROXY=1` (иначе ограничение входа будет считать всех одним человеком):
   `TRUST_PROXY=1 npm start` (в Windows PowerShell: `$env:TRUST_PROXY=1; npm start`).

Адрес меняется при каждом запуске туннеля. Постоянный адрес можно получить с бесплатным аккаунтом Cloudflare и своим доменом.

## Способ 2. Сервер (VPS) + Docker, рекомендуется

Это то, что нужно, чтобы мессенджер работал всегда. Для 2–3 человек хватит самого дешёвого сервера
(1 процессор, 1 ГБ памяти, 10–20 ГБ диска), без ИИ-ассистента.

**Что нужно купить или получить**
- VPS с Ubuntu 22.04 или 24.04. Подойдёт любой провайдер (из российских: Timeweb Cloud, Selectel, Beget, REG.RU;
  из зарубежных: Hetzner, DigitalOcean, Vultr и т.п.). Цены и способы оплаты проверьте на сайте провайдера: они меняются.
- Домен (например, `chat.ваш-домен.ru`) и A-запись, указывающая на IP сервера. Без домена нет HTTPS, а без HTTPS
  небезопасно: пароли пойдут открытым текстом. Поддомен на уже имеющемся домене стоит бесплатно.

**Шаги** (на сервере по SSH)
```bash
# 1. Docker
curl -fsSL https://get.docker.com | sh

# 2. Загрузите проект (например, с вашего компьютера):
#    scp messenger.zip root@IP_СЕРВЕРА:~   затем на сервере:
apt-get install -y unzip && unzip messenger.zip && cd messenger

# 3. Настройки
cp .env.example .env
nano .env            # впишите DOMAIN=ваш.домен, при желании APP_NAME

# 4. Запуск (HTTPS-сертификат Caddy получит сам)
docker compose up -d --build
```
Откройте `https://ваш.домен`. Порты 80 и 443 должны быть открыты в файрволе провайдера.

**Сразу после запуска**
1. Зарегистрируйтесь первым: первый аккаунт становится администратором.
2. Меню ☰, Admin panel, вкладка Access: поставьте «Invite only» и создайте по коду на каждого друга.
   Без этого регистрироваться сможет любой, кто узнает адрес.
3. Отправьте друзьям адрес и код. Забыл пароль: вкладка Users, «Reset password».

**Обновление версии:** распакуйте новый архив поверх (папки `data` и `uploads` не трогайте), затем `docker compose up -d --build`.

## Способ 3. Сервер без Docker

1. Установите Node.js 22.5 или новее и Caddy (или nginx).
2. Распакуйте проект в `/opt/messenger`, выполните `npm install && npm run build`.
3. Скопируйте `deploy/messenger.service` в `/etc/systemd/system/`, поправьте пользователя и пути,
   затем `systemctl enable --now messenger`.
4. Caddy: в `/etc/caddy/Caddyfile` напишите `ваш.домен { reverse_proxy 127.0.0.1:3000 }`.

## Резервные копии (важно)

Все сообщения лежат в `data/messenger.db`, файлы в `uploads/`. Копия базы на ходу:
```bash
node scripts/backup.js          # в Docker: docker compose exec app node scripts/backup.js
```
Создаёт `backups/messenger-ДАТА.db` и хранит 14 последних. Раз в день запускайте из cron
(`0 4 * * * cd /opt/messenger && node scripts/backup.js`) и периодически копируйте папку `backups` и `uploads`
к себе на компьютер. Если сервер потеряется без копии, переписки не вернуть.

## ИИ-ассистент на сервере

Маленькому серверу локальная модель не по силам, поэтому в `.env.example` стоит `AI_ENABLED=0`: ассистент отключён.
Варианты: оставить так; или запустить Ollama на своём компьютере с хорошей видеокартой и указать серверу его адрес
через `AI_URL` (связать компьютер и сервер лучше через VPN вроде Tailscale, не открывая Ollama в интернет).

## Что учесть

- Вы владелец данных: вы технически можете читать сообщения на сервере (сквозного шифрования нет). Скажите об этом друзьям.
- Обновляйте систему сервера (`apt update && apt upgrade`) и не отключайте HTTPS.
- Нет push-уведомлений, когда вкладка закрыта, и нет восстановления пароля по почте (только через админа).
